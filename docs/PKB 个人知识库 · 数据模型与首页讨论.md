#### 一、数据模型（细化版）

##### 争议点 2 落地：`content_format` 到底怎么存

你说「Markdown 为主 + 保留富文本」，有三种解释，我列出来让你选：

| 方案                                   | 存法                                               | 优点                               | 缺点                                                     |
| :------------------------------------- | :------------------------------------------------- | :--------------------------------- | :------------------------------------------------------- |
| **A（推荐）** 一条笔记**只有一种格式** | `content` 存原文，`content_format` = `md` / `html` | 简单、渲染路径清晰；编辑时格式不变 | 一条笔记里不能混排                                       |
| B 两列都存                             | `content_md` + `content_html`，互为镜像            | 想渲染随时切                       | 双份存储、双份清洗、同步易漂，**典型的「过度设计」**     |
| C 只存 md，富文本视图实时转 md         | `content` 全 md，富文本编辑器提交前转 md           | 数据同源                           | 富文本 → md 转换是有损的（表格/对齐/嵌套列表），会丢东西 |

- 复用原项目富文本链路时**只是多一个编辑入口**，不动存储层
- 后端清洗逻辑按 `content_format` 分流：`html` 走 jsoup 入库清洗；`md` 存原文，**渲染端 DOMPurify 兜底**
- 未来想「md 转富文本」也随时能做，因为它只是 A 之上的一个转换动作，不是数据模型变更

**你认可 A 吗？** 若认可，字段就定成：

